# looprs 0.6.0

Released 2026-09-19.

## What's New

### Versioned automation protocol

Scripted runs can opt into `looprs-machine/v1`, a JSONL protocol emitted on stderr. Every event
includes a stable run ID, sequence number, timestamp, event kind, and structured data. Runs emit
started and terminal events, include token usage on success, and can be stopped with a relative
deadline or cancellation file.

```bash
looprs -p "check this repository" \
  --machine-protocol looprs-machine/v1 \
  --run-id ci-42 \
  --deadline-seconds 300 \
  --cancel-file /tmp/looprs-ci-42.cancel
```

Assistant and human-readable output remain on stdout, so automation can consume machine events
from stderr independently. Existing `--machine-log` integrations retain the legacy top-level
`{kind,data}` format.

### Parallel delegated tools and MCP composition

Delegated turns configured with the `parallel` orchestration strategy can execute independent tool
calls concurrently up to `max_parallel`; results are returned to the provider in its original call
order. Setting `LOOPRS_MCP_SERVER_URL` adds tools discovered from an MCP server to the built-in
catalog. Built-in tools win name conflicts, and configured fallback execution remains available if
the remote call fails.

### Managed plugin daemons

Tool, runtime, and orchestration plugins can now run as supervised daemons. looprs launches enabled
daemon entries without shell expansion, tracks process IDs and health, supports optional probes,
bounds restarts to three attempts, and stops managed children when they are replaced, removed, or
shut down.

### Cross-session observations

The observation API can query recent records across sessions, filter by tool, and replay a previous
session into the current runtime cache. SQLite reads are deterministic and read-only: they validate
the existing schema rather than silently creating or migrating a database.

## Improvements

- OpenAI and Anthropic streaming now carries text, tool-call fragments, final structured content,
  stop reasons, and token usage through one provider request per inference step.
- Delegated agent preparation now lives in the runtime, giving CLI, library, and future frontends
  the same agent-selection, skill-resolution, and capability policy.
- Provider aliases and settings use one descriptor registry, keeping CLI selection and runtime
  construction consistent for Anthropic, OpenAI, Gemini, local Ollama, SDK-backed providers, and
  BAML.
- Expanded pipelines now report tool availability, rewards, benchmarks, fail-fast behavior, and
  logging failures while the legacy check-only API keeps its established report and step order.
- A static reference site now documents architecture, crate ownership, state, feature support,
  testing, stability, changelog, and roadmap, with automated link and asset validation.

## Bug Fixes

- Streaming tool calls and usage are no longer lost when providers split them across multiple
  deltas, and tool turns no longer trigger a duplicate inference request.
- Deadlines and cancellation files now interrupt in-flight machine runs and produce a single
  `run.cancelled` terminal event with a stable reason.
- Plugin reloads are transactional: an invalid replacement no longer discards a healthy running
  registry, and replaced or removed processes are stopped safely.
- Observation queries no longer create databases during reads, replay is idempotent, timestamp
  collisions retain distinct records, and malformed rows or schemas return precise errors.
- Skill discovery now honors configured repository paths, supports root `.yaml` and `.yml` files in
  deterministic order, and reports inaccessible directories instead of silently hiding them.
- MCP discovery has a bounded timeout, malformed responses are rejected, and failed remote
  discovery does not remove the built-in catalog.
- Trace freshness checks now fail stale for missing, unreadable, malformed, invalid-timestamp, or
  pre-Unix-epoch inputs instead of treating uncertain data as current.

## Breaking Changes

### Construct `RuntimeSettings` through its stable API

`RuntimeSettings` adds parallel-dispatch and MCP options and is now non-exhaustive. Replace direct
struct literals:

```rust
let settings = RuntimeSettings::new(defaults, max_tokens_override, fs_mode)
    .with_max_parallel(4)
    .with_mcp_server_url("http://127.0.0.1:3000");
```

Omit either builder to retain its default. Existing reads of public fields remain supported. See
[`docs/migration-0.6.md`](../migration-0.6.md) for the full construction and release-gate guidance.

### Update custom streaming providers

`InferenceProvider::infer_stream` now returns typed `InferenceStreamEvent` values rather than plain
text chunks. Custom implementations must emit zero or more `Delta` events followed by exactly one
`Final(InferenceResponse)` event. Text uses `InferenceDelta::Text`; incremental tool calls use
`InferenceDelta::ToolCall`. Providers that rely on the trait's default implementation require no
change.

### Make custom tool executors asynchronous

The execution port is now asynchronous and is exposed as `ToolDispatcher`, with `ToolExecutor`
retained as a compatibility name. Add `#[async_trait::async_trait]`, make `execute` async, and await
calls. Embedders that provide both tool definitions and execution should construct `ToolPorts` from
a `ToolCatalog` and `ToolDispatcher`, then pass it through
`Agent::new_with_runtime_and_tool_ports` or `Agent::with_tool_ports`.

### Update plugin supervision implementations and manifests

Custom supervisors must implement `PluginSupervisorPort` with typed `status`, `probe`, `restart`,
and `shutdown` operations, then implement the applicable marker traits (`ToolSupervisorPort`,
`RuntimeSupervisorPort`, or `OrchestrationSupervisorPort`). Code that constructs
`PluginSupervisorStatus` must also provide `pid`, `last_error`, and `last_restart_reason`.
Rust code that constructs `PluginEntry` directly must add `args` and `probe` fields.

Enabled daemon manifests must include a non-empty executable and put arguments in `args`:

```yaml
name: local-tool-service
kind: tool
mode: daemon
entry:
  command: local-tool-service
  args: ["serve", "--stdio"]
  probe:
    command: local-tool-service
    args: ["health"]
```

Malformed manifests now fail registry loading instead of being skipped. One-shot manifests remain
compatible and do not require an `entry`.

### Fix invalid skill and delegation configuration

Skill `name`, every `triggers` entry, and skill content must contain non-whitespace text. Root YAML
skills use `content`; nested `SKILL.md` files use the Markdown body. A delegated agent that names a
missing skill now fails closed, so add the skill to the configured user or repository skill path or
remove it from the agent definition.

## Compatibility and Validation

- The workspace remains on Rust 1.88.0 and publishes version 0.6.0 for its workspace crates.
- Legacy `--machine-log` records remain supported; versioned run controls require
  `--machine-protocol looprs-machine/v1`.
- Release validation checks public API compatibility for `looprs-core`, `looprs`, and `looprs-tui`,
  requires health artifacts for the exact release version, and validates checksums, SBOMs, and the
  complete Linux x86_64, macOS ARM64, and Windows x86_64 asset set.
- Fresh gates pass all 677 workspace tests, and fresh core coverage is 90.3%.
- Workspace and fuzz lockfiles retain `quinn-proto 0.11.17` for the security remediation recorded
  in the 0.5.5 changelog.
