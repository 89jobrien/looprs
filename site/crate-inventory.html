Boundary notes

Core contract

looprs-core remains the neutral place for stable shared types used by higher layers.

Runtime ownership

looprs owns orchestration logic; CLI and TUI should avoid leaking runtime internals into their own layers.

Crate ownership quick guide

  • looprs-core: add or evolve shared types, events, and port contracts.
  • looprs: add runtime behavior, provider wiring, tools, hooks, and policy loops.
  • looprs-cli: add flags, command UX, and shell-facing integration.
  • looprs-tui: add terminal interaction flows and display behavior.
  • looprs-macros: add compile-time ergonomics helpers.
  • xtask: add project automation and verification commands.
