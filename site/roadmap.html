Roadmap

Implemented foundations, active priorities, and next runway for looprs.

Horizon
Now to next release
Primary focus
Reliability and orchestration
Secondary focus
MCP and observability depth

Shipped baseline

  1. Runtime + extension framework: core loop, provider adapters, built-in tools, hooks, skills, commands, and rules are in regular use.
  2. Multi-surface UX: CLI REPL, provider menu, and TUI workflows are wired over the same runtime with observability traces.

Active priorities

  1. P1 - Delegation hardening: continue tightening delegated capability boundaries and improving explicit policy visibility.
  2. P1 - Streaming reliability: expand streaming/tool-call compatibility tests and reduce edge-case divergence across providers.
  3. P2 - MCP integration depth: improve remote tool composition ergonomics and fallback behavior when remote endpoints degrade.
  4. P2 - Observability workflows: refine diagnostics capture and replay for faster triage during complex multi-turn sessions.

Operational next steps

  1. Broaden integration tests for CLI + TUI paths under the same runtime conditions.
  2. Document capability boundaries and extension ownership with release-level clarity.
  3. Add more end-to-end examples for repo-local .looprs composition patterns.

Dependencies and sequencing

  1. Stabilize streaming and delegation tests first: this de-risks subsequent MCP and plugin changes.
  2. Expand observability schemas second: enables clear diagnostics while larger integration work lands.
  3. Finalize docs and examples third: ensure extension authors can adopt changes without guesswork.

Exit criteria for this roadmap slice

  • [verified] delegated capability boundaries are enforced in advertised and executed tool paths.
  • [verified] streaming and non-streaming tool paths continue until a terminal assistant response.
  • [in progress] pre-push and workflow smoke gates remain green as integration continues.
  • [in progress] docs and examples are checked against each integrated wave.
