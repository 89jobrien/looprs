Testing and Gates

Quality checks used in regular development and pre-push hooks.

Primary commands

cargo build --workspace

cargo nextest run --workspace

cargo clippy --all-targets --all-features -- -D warnings

cargo xtask check pre-push

If you only run one command before publishing branch updates, run cargo xtask check pre-push since it captures formatting, linting, tests, and project-specific validation parity.

Gate intent

Compilation and lint

Catch API drift, dead code, and warning regressions across crates before integration.

Behavioral tests

Exercise tool execution, provider adapters, file-reference behavior, and runtime state.

Protocol drift checks

Validate contract surfaces used for taskit protocol locking and workspace consistency.

Coverage and regressions

Pre-push checks include targeted crate coverage and fail fast on integration-breaking changes.

Live model tests

Optional live-provider tests are gated to avoid accidental external calls: LOOPRS_RUN_LIVE_LLM_TESTS=1.

Release or integration branchcargo xtask check pre-pushfull pre-push plus manual smoke run

Debugging failed gates

  1. Fix formatting first so lint and test diffs stay readable.
  2. Resolve clippy warnings before broad test retries.
  3. Re-run only the failing crate while iterating.
  4. End with full workspace or pre-push parity before commit/push.
