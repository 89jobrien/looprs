Stability Checklist

A practical gate list for landing and maintaining reliable looprs changes.

Operational interpretation

Green branch means

  • Formatting and linting match repository standards.
  • Workspace behavior is validated under nextest.
  • Project-specific drift and policy checks are clean.

Red branch means

  • Do not push additional risky changes.
  • Isolate failing scope before widening edits.
  • Recover gate parity before merge or release actions.

Release discipline

Before merge

Keep branch green with full gate parity and conflict-free integration evidence.

Before push

Run pre-push checks locally and ensure no unresolved OPAVS phase gate transitions.

Pre-push readiness checklist

  1. Run cargo fmt --all.
  2. Run cargo clippy --all-targets --all-features -- -D warnings.
  3. Run cargo nextest run --workspace for behavior parity.
  4. Run cargo xtask check pre-push for project gates.
  5. Confirm branch state and intended phase gates before pushing.
Stability is not just test count. It is repeatability: same branch, same inputs, same outcome across local and CI-style gates.
